Every agent demo dies on turn three.

Turn one: model calls a tool, gets a result. Turn two: it calls another. Turn three: context is bloated, the plan it made on turn one is gone, and if you gave it file access it just overwrote the wrong file with no way back. The agent didn't fail because of a bad model — it failed because nothing around the model was built for multi-step work.

[DeepAgents](https://github.com/langchain-ai/deepagents) is LangChain's answer: an opinionated harness that ships the six things a long-horizon agent actually needs, built on LangGraph so every piece is production-grade from day one.

## <Label color="teal">1</Label> The six gaps that kill demo agents

A vanilla tool loop handles `one prompt + one tool`. It breaks on anything longer because it was never designed for it.

<Card accent="teal" flush={true}>

```py
while not done:
    result = call_model(context)         # context grows unbounded
    if result.tool_call:
        context.append(run_tool(result)) # no isolation, no rollback
    else:
        done = True                      # plan from turn 1 is gone
```

### Layer 2 — Context Management

This is how the agent survives past turn three.

- **Skills** — directories with `SKILL.md` following the [Agent Skills standard](https://agentskills.io/). Loaded with *progressive disclosure*: frontmatter at startup, full content only when a task needs it.
- **Memory** — `AGENTS.md` files passed via `memory=` param, persisted in `StateBackend | StoreBackend | FilesystemBackend`. The agent can update memory from feedback so conventions carry forward.
- **Summarization + Offloading** — builtin compression of conversation history and large tool outputs. Subagents add isolation (heavy work stays out of the main window) and the virtual filesystem adds long-term memory across threads.
- **Prompt caching** — automatic for Anthropic/Bedrock (Claude, Nova) on static sections; pluggable for other providers.

### Layer 3 — Delegation

<Concept term="Sub-agent" category="pattern">
  A sub-agent is an ephemeral child agent spawned by the `task` tool. It gets a **fresh context window**, runs autonomously on one delegated goal, and returns a single compact report. Heavy work is quarantined — failures, noise, and bloat stay inside the sub-agent and never reach the main context.
</Concept>

Two complementary pieces:

- **Task planning** — opt-in via `TodoListMiddleware` → exposes `write_todos` tool. Tasks are `pending → in_progress → completed` and persisted in state. Useful for long runs, weaker models that need accountability, or UIs that stream progress.
- **Sub-agents** — the `task` tool spawns isolated child agents in parallel. Disable via `excluded_tools: [task]` on the harness profile — don't try to remove `SubAgentMiddleware`.

### Layer 4 — Steering

<Concept term="Human-in-the-loop" category="pattern">
  HITL in DeepAgents is a LangGraph interrupt: the run pauses *before* a named tool executes, surfaces the pending call to a human, and resumes only after approval, edits, or rejection. It's structural, not conversational — the model can't talk its way past it.
</Concept>

```py
agent = create_deep_agent(
    model="openai:gpt-5.5",
    interrupt_on={"edit_file": True, "execute": True}
)
# pauses before every edit/execute — approve, add guidance, or modify inputs
```

Filesystem permissions use exactly two operations — `read` and `write` (which covers `write_file`, `edit_file`, and `delete`). Rules are evaluated top-down, first-match-wins:

<EnforceRule
  methodLabel="Op"

The `mode` field on each permission also accepts `"interrupt"` instead of `"deny"` — this pauses execution for human approval rather than blocking outright. Sandboxes enforce boundaries at the tool level independently.

## <Label color="amber">3</Label> The middleware stack

Under the hood, DeepAgents is a declarative ordering of middleware over LangGraph. Every piece is replaceable — pass a custom `FilesystemMiddleware(tools=[...])`, swap the sub-agent definition, or wire in a hand-built `CompiledStateGraph` as a worker:

<DiagramEmbed
  src="/diagrams/deepagents-middleware-stack.html"
  title="DeepAgents Middleware Stack Composition"
  height={540}
/>

- **Override any piece without forking** — pass custom middleware via `middleware=` / `subagents=`; the stack is declarative.
- **Any `CompiledStateGraph` is a sub-agent** — drop a hand-built LangGraph workflow in as a delegated worker.
- **Model-agnostic** — frontier (OpenAI, Anthropic, Google), open-weight (Baseten, Fireworks), or local (Ollama, vLLM, llama.cpp) — anything with tool calling and a LangChain chat model wrapper.
- **DeepAgents Code** — a pre-built terminal coding agent (Claude Code / Cursor analog) powered by any LLM: `curl -LsSf https://langch.in/dcode | bash`.

### Minimal code

```py
# uv add deepagents
from deepagents import create_deep_agent

def my_tool(query: str) -> str:
    return f"result for {query}"

agent = create_deep_agent(
    model="openai:gpt-5.5",
    tools=[my_tool],
    system_prompt="You are a research assistant.",
    # interrupt_on={"edit_file": True},      # HITL
    # permissions=[{"paths": [".env"], "mode": "deny"}],
    # memory=["./AGENTS.md"],
    # middleware=[TodoListMiddleware()],
)

result = agent.invoke({"messages": "Research LangGraph and write a summary"})
print(result["messages"][-1].content)
```

<Concept term="Context Collapse" category="failure mode">
  Context collapse is what kills long-horizon agents. As turns accumulate, the context window fills with tool outputs, intermediate thoughts, and stale plan fragments. The model's effective attention span shrinks to the last few thousand tokens. DeepAgents avoids it through summarization, offloading to the virtual filesystem, and sub-agent isolation — the main agent never sees the full output of heavy subtasks.
</Concept>

<Callout color="amber">
  Rule of thumb: use **DeepAgents** when you want harness defaults for planning, delegation, and context management. Use **create_agent** when you want less bundle. Drop to **LangGraph** when the agent loop itself is the wrong shape.
</Callout>
