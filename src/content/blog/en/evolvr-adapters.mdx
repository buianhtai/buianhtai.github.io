## <Label color="teal">1</Label> Why Hooks for the Write Path

<Card>

Claude Code exposes a hook system in `~/.claude/settings.json` (or the project-level `.claude/settings.json`). Hooks are shell commands that fire at defined lifecycle events: before a tool call, after a tool call, and when the session stops. They run asynchronously — the agent does not wait for them to complete.

This is exactly the right integration point for evolvr's write path. The hook fires, calls `evolvr hook`, the journal records the event, and the agent continues. No latency added to the agent's execution loop.

Three hook events are used:

- **PreToolUse** — fires before each tool call. evolvr records the tool name and sequence number.
- **PostToolUse** — fires after each tool call with result metadata. evolvr records args hash, result hash, result summary, and latency.
- **Stop** — fires when the session ends. evolvr finalizes the task record and runs the failure classifier.

</Card>

## <Label color="green">2</Label> The Hook Command — `evolvr hook`

<Card>

The `evolvr hook` command is the CLI's write path. It handles all four hook event types and routes to the correct journal operation.

**Full hook configuration (`~/.claude/settings.json`):**

```json
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "*",
      "hooks": [{
        "type": "command",
        "command": "evolvr hook --event pre-tool --task $CLAUDE_SESSION_ID --tool $TOOL_NAME"
      }]
    }],
    "PostToolUse": [{
      "matcher": "*",
      "hooks": [{
        "type": "command",
        "command": "evolvr hook --event post-tool --task $CLAUDE_SESSION_ID --tool $TOOL_NAME --args-hash $ARGS_HASH --result-hash $RESULT_HASH --latency $LATENCY_MS"
      }]
    }],
    "Stop": [{
      "hooks": [{
        "type": "command",
        "command": "evolvr hook --event stop --task $CLAUDE_SESSION_ID --outcome success"
      }]
    }]
  }
}
```

The `$CLAUDE_SESSION_ID`, `$TOOL_NAME`, `$ARGS_HASH`, `$RESULT_HASH`, and `$LATENCY_MS` variables are provided by Claude Code. The args and result hashes are computed by Claude Code itself — evolvr receives pre-hashed values and stores them directly, which means no raw argument content ever passes through the `evolvr hook` command.

</Card>

<Callout color="teal">
Claude Code computing the hashes before the hook fires is a key privacy boundary. evolvr never sees raw tool arguments. It only sees SHA-256 hashes, result summaries (first 200 chars), and structural metadata like latency and sequence number.
</Callout>

## <Label color="amber">3</Label> Hook Command Internals

<Card>

Inside `@evolvr/cli`, the `hook` command routes each event to the corresponding journal operation:

```typescript
// packages/cli/src/commands/hook.ts
import { Evolvr } from '@evolvr/core';

interface HookOptions {
  event: 'start' | 'pre-tool' | 'post-tool' | 'stop';
  task: string;          // session ID from $CLAUDE_SESSION_ID
  tool?: string;
  argsHash?: string;
  resultHash?: string;
  latency?: number;
  outcome?: string;
}

export async function hookCommand(opts: HookOptions): Promise<void> {
  const evolvr = await Evolvr.load();  // reads .evolvr/config.json

  switch (opts.event) {
    case 'start': {
      await evolvr.startTask({ id: opts.task, agent: 'claude' });
      break;
    }
    case 'pre-tool': {
      await evolvr.recordPreTool({
        taskId: opts.task,
        tool: opts.tool!,
      });
      break;
    }
    case 'post-tool': {
      await evolvr.recordPostTool({
        taskId: opts.task,
        tool: opts.tool!,
        argsHash: opts.argsHash!,
        resultHash: opts.resultHash!,
        latencyMs: opts.latency ?? 0,
      });
      break;
    }
    case 'stop': {
      const result = await evolvr.completeTask({
        taskId: opts.task,
        outcome: (opts.outcome ?? 'success') as 'success' | 'partial' | 'failed',
      });
      // Run classifier — sync, fast (rule-based only in v0.1)
      if (result.outcome !== 'success') {
        await evolvr.classify(opts.task);
      }
      break;
    }
  }
}
```

The `Evolvr.load()` call reads `.evolvr/config.json` from the project root (or `~/.evolvr/config.json` as a fallback). Each hook invocation is a standalone CLI process — no persistent daemon required.

</Card>

## <Label color="rose">4</Label> The MCP Server Implementation

<Card>

`@evolvr/mcp` is a thin MCP server layer over `@evolvr/core`. It starts a persistent process that Claude Code (or any MCP client) connects to via stdio.

**Server initialization:**

```typescript
// packages/mcp/src/index.ts
import { Server } from '@modelcontextprotocol/sdk/server/index.js';
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js';
import { Evolvr } from '@evolvr/core';
import { registerTools } from './tools.js';

async function main() {
  const projectRoot = process.argv[2] 
    ? process.argv[process.argv.indexOf('--project-root') + 1]
    : process.cwd();

  const evolvr = await Evolvr.load({ root: projectRoot });

  const server = new Server(
    { name: 'evolvr', version: '0.1.0' },
    { capabilities: { tools: {} } }
  );

  registerTools(server, evolvr);

  const transport = new StdioServerTransport();
  await server.connect(transport);
}

main().catch(console.error);
```

**Tool registration:**

```typescript
// packages/mcp/src/tools.ts
export function registerTools(server: Server, evolvr: Evolvr) {
  server.setRequestHandler(ListToolsRequestSchema, async () => ({
    tools: [
      {
        name: 'evolvr_get_lessons',
        description: 'Get learned lessons relevant to the current task for system prompt injection.',
        inputSchema: {
          type: 'object',
          properties: {
            text: { type: 'string', description: 'Task description or first message' },
            agent: { type: 'string', description: 'Agent type filter (claude, opencode, codex)' },
            limit: { type: 'number', description: 'Max lessons to return (default 5)' },
          },
          required: ['text'],
        },
      },
      // ... evolvr_record_tool_call, evolvr_session_end, evolvr_get_status
    ],
  }));

  server.setRequestHandler(CallToolRequestSchema, async (req) => {
    switch (req.params.name) {
      case 'evolvr_get_lessons': {
        const lessons = await evolvr.getLessons({
          text: req.params.arguments.text as string,
          agent: req.params.arguments.agent as string | undefined,
          limit: req.params.arguments.limit as number | undefined,
        });
        return {
          content: [{ type: 'text', text: formatLessons(lessons) }],
        };
      }
      // ... other tool handlers
    }
  });
}
```

</Card>

<Callout color="rose">
The MCP server runs as a persistent child process. Claude Code starts it on the first tool call and keeps it alive for the session. This means the `Evolvr.load()` call and database connection happen once per session, not once per tool call — unlike the hook command which is a fresh process each time.
</Callout>

## <Label color="violet">5</Label> The Shared Journal — One Database, Two Surfaces

<Card>

Both the hook pipeline and the MCP server write to the same journal database. The hook command handles writes (pre-tool, post-tool, stop), and the MCP server handles reads (`evolvr_get_lessons`, `evolvr_get_status`).

Write/read concurrency is handled by libsql's WAL mode:

```typescript
// packages/core/src/adapters/sqlite.ts
import { createClient } from '@libsql/client';

export function createSQLiteAdapter(path: string) {
  const client = createClient({ url: `file:${path}` });

  // WAL mode: concurrent reads alongside writes
  await client.execute('PRAGMA journal_mode = WAL');
  await client.execute('PRAGMA foreign_keys = ON');

  return client;
}
```

The hook command (write path) and MCP server (read path) can operate concurrently without blocking. Hook writes are fast — a single `INSERT` or `UPDATE` per call. MCP reads are queries over indexed columns. No contention in practice.

For teams using PostgreSQL, the same `@evolvr/core` adapters work with a Postgres URL — no code changes, just config:

```json
{
  "storage": {
    "type": "postgres",
    "url": "postgresql://user:pass@host:5432/evolvr"
  }
}
```

</Card>

## <Label color="teal">7</Label> Getting Started

<Card>

**Install:**

```bash
npm install -g @evolvr/cli
# also installs evolvr-mcp binary
```

**Initialize in a project:**

```bash
cd my-project
evolvr init
# creates: .evolvr/config.json, evolvr.db
```

**Add the MCP server to Claude Code:**

```json
// ~/.claude/mcp.json
{
  "mcpServers": {
    "evolvr": {
      "command": "evolvr-mcp",
      "args": ["--project-root", "/path/to/my-project"]
    }
  }
}
```

**Add hooks to Claude Code:**

```json
// ~/.claude/settings.json — add the hooks block shown in section 2
```

**Day-to-day commands:**

```bash
evolvr status                           # journal stats
evolvr tasks --outcome failed --limit 20  # recent failures
evolvr tasks --agent claude --show-tool-calls  # with tool call detail
evolvr lessons                          # active lessons
evolvr lessons --class exact_repeat_loop  # filter by class
evolvr lessons --promote                # mark lessons for AGENTS.md (v0.3)
```

</Card>

## <Label color="violet">8</Label> What's Next

<Card>

The v0.1 series covered evolvr's shipped MVP. The roadmap:

**v0.2 — Semantic classifier**
- Stage 2 LLM classification enabled by default
- Embedding-based lesson retrieval in `evolvr_get_lessons` (not just keyword matching)
- Vector index on lesson content for context-relevant lookup

**v0.3 — AGENTS.md auto-promotion**
- Evidence-gated patch generation (3+ instances required)
- Human review gate via `evolvr lessons --promote`
- A/B shadow testing over 10 matching runs before permanent commit

**v0.4 — Broader agent support**
- OpenCode plugin (event bus subscriber)
- Codex provider client wrapper
- Cross-project lesson sharing and global lesson scope

The project is at [github.com/buianhtai/evolvr](https://github.com/buianhtai/evolvr). Packages are in `packages/core`, `packages/cli`, and `packages/mcp`.

</Card>

<Callout color="sky">
If you're using Claude Code daily, the hook + MCP setup takes about 5 minutes and immediately starts building a failure record. After a week of normal use, `evolvr lessons` will show the patterns Claude keeps hitting in your specific codebase.
</Callout>
