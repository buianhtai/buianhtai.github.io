**What happens when a user asks an AI coding agent to investigate a failing test?** DeepSeek Harness offers a useful architecture lesson: the model is only one part of the system. The agent loop coordinates a prompt builder, model adapter, tool-execution pipeline and session event log.

The interactive guide below starts with **one connected system diagram**. Follow the numbered request path; click any component or stage to see its purpose and the exact source code behind it.

## Why does this matter?

The main design idea is **separation of responsibilities**. The agent driver coordinates work; the model generates proposals; tools enforce guards and approvals; the session keeps durable facts. Cordis makes these capabilities composable through service contracts, so different runtime profiles can swap implementations without rebuilding the entire agent.

The diagrams show **in-process logical boundaries**, not a distributed network of microservices. The seven steps are source-guided, not a complete runtime trace. The project remains a developer preview and has not been security-audited; see its [safety limitations](https://github.com/deepseek-ai/deepseek-harness/blob/1517a4dbca0a2789ff1d41ba439600f8547d23fa/SAFETY.md).
