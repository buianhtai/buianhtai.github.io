**An agent is more than a model and a while-loop.** It also needs tools, permissions, state, streaming and reliable boundaries. DeepSeek Harness explores what happens when *even those capabilities—and the agent loop itself—are plugins*.

## What makes the architecture worth studying?

**Three unusual decisions** distinguish [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) from a minimal tool-calling loop.

**Replaceable runtime:** [Cordis](https://github.com/cordiverse/cordis) supplies service injection, typed events and reversible plugin registrations. The model adapter, tools, session providers, prompt assembly and agent driver can be composed from ordered profiles and bundles.

**Reconstructable context:** the session event log is the source of model-visible state, while `agent/*` events drive live coordination and transient UI streaming. A streamed chunk isn't automatically a committed assistant response.

**Tool authorization outside the prompt:** tool guards, approvals, execution wrappers and result normalization sit in the capability pipeline. An instruction to the model is not the authorization boundary.

## What not to copy blindly

DeepSeek Harness is **developer-preview software**, not an audited production security boundary. Plugin flexibility creates lifecycle, ordering and configuration complexity. Its session log doesn't automatically make external side effects exactly-once, and an in-process Cordis service is not a distributed job queue.

For an enterprise platform, borrow the interfaces and session/event distinctions, then add your own tenant isolation, worker leasing, secret management, audit retention, idempotency, approvals and cost controls.
