A customer emails at 11pm: *"Getting 401s since 3pm, blocking our release."* Your on-call engineer opens four browser tabs — docs, logs dashboard, admin panel, runbook — and starts the same manual investigation they've done a hundred times.

This post wires [DeepAgents](https://github.com/langchain-ai/deepagents) to do that investigation automatically: ingest your KB into a searchable store, connect your platform via MCP, and run a troubleshooting agent that diagnoses the issue and proposes a fix — pausing for human approval before touching anything.

**Scenario throughout this post:** StreamAPI, a fictional SaaS platform. Customer `tai@streamapi.io` is getting 401 errors. We'll build the agent that figures out why.

This is the implementation-level companion to [Building Support Agents for Your Platform](/en/blog/building-support-agents-for-your-platform/), which covers the broader multi-agent topology, observability architecture, tenancy, evaluation, and production trade-offs. This post deliberately narrows to one DeepAgents-powered technical-support lane: KB retrieval + platform MCP tools + human approval before writes. It complements that architecture post; it does not replace it.

## <Label color="green">2</Label> Retrieval is a strategy, not a single index

<Concept term="Why not just embed everything into one vector store?" category="design">
  Vector similarity works for semantic questions, but breaks on exact lookups: "does the GET /orders endpoint accept a cursor parameter?" or "how many APIs do we have?" need structured access, not nearest-neighbour search. The agent decides which strategy fits the query — and retries with the next best option if the first returns insufficient evidence.
</Concept>

The target flow is:

## <Label color="teal">3</Label> Ingestion — two tracks

There are two distinct knowledge sources. They use separate ingest paths and feed the same tenant-scoped PostgreSQL retrieval layer:

- **Track A — Customer uploads**: PDFs, DOCX, images. Binary-safe streaming from the download API; Sonnet handles images. Output: prose chunks indexed by PostgreSQL full-text search and pgvector.
- **Track B — OKF bundle**: Platform-maintained structured knowledge — API contracts, policies, metrics, known issues — authored as [OKF](https://github.com/GoogleCloudPlatform/open-knowledge-format) markdown concepts with YAML frontmatter. Frontmatter populates relational columns for exact queries; the body enters the same full-text and vector indexes.

OKF does not replace OpenAPI or document-upload formats. An `API Endpoint` concept links to the canonical OpenAPI resource; customer files remain ordinary PDF, DOCX, or image payloads.

One OKF concept is just a Markdown file. For an endpoint, keep the machine-queryable fields in frontmatter and the support guidance in the body:

```markdown
---
type: API Endpoint
title: GET /orders
description: List orders with cursor pagination
resource: openapi.yaml#/paths/~1orders/get
tags: orders,pagination
status: current
stale_after: 2026-12-31
---

# GET /orders

Use `cursor` from the previous response's `next_cursor` field.
A missing cursor starts from the newest order. A malformed cursor returns `400`.
```

```python
# ingest_worker.py
import base64, hashlib, os, psycopg, tempfile, yaml
from pathlib import Path
from langchain_aws import BedrockEmbeddings
from langchain_postgres import PGVector
from langchain_community.document_loaders import PyPDFLoader, UnstructuredFileLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_litellm import ChatLiteLLM
from langchain_core.documents import Document
from langchain_core.document_loaders import BaseLoader
import httpx

embeddings = BedrockEmbeddings(
    model_id="amazon.titan-embed-text-v2:0",
    region_name=os.environ.get("AWS_REGION", "us-east-1"),
)
vision = ChatLiteLLM(          # Sonnet 5 via LiteLLM for image-to-text
    model=os.environ["LLM_MODEL"],
    api_base=os.environ.get("LITELLM_API_BASE"),
)
IMAGE_TYPES = {"image/png", "image/jpeg", "image/webp"}
SUFFIXES = {
    "application/pdf": ".pdf",
    "application/vnd.openxmlformats-officedocument.wordprocessingml.document": ".docx",
    "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet": ".xlsx",
    "text/plain": ".txt", "text/markdown": ".md",
    "image/png": ".png", "image/jpeg": ".jpg",
}
OKF_RESERVED = {"index.md", "log.md"}


# ── Track A: Customer uploads ─────────────────────────────────────────────────

class PlatformFileLoader(BaseLoader):
    """Stream bytes from the download API; dispatch to the right parser."""
    def __init__(self, file_id: str, tenant_id: str):
        self.file_id, self.tenant_id = file_id, tenant_id

    def lazy_load(self):
        with httpx.stream(
            "GET",
            f"{os.environ['PLATFORM_API_BASE']}/files/{self.file_id}/download",
            headers={"X-Tenant-ID": self.tenant_id}, timeout=60,
        ) as resp:
            resp.raise_for_status()
            ct = resp.headers.get("content-type", "").split(";")[0].strip()
            suffix = SUFFIXES.get(ct, ".bin")
            with tempfile.NamedTemporaryFile(suffix=suffix, delete=False) as tmp:
                for chunk in resp.iter_bytes():
                    tmp.write(chunk)
                tmp_path = tmp.name

        meta = {"file_id": self.file_id, "tenant_id": self.tenant_id}
        if ct in IMAGE_TYPES:
            # Sonnet multimodal: images → text description → indexed prose
            data = Path(tmp_path).read_bytes()
            msg = vision.invoke([{"role": "user", "content": [
                {"type": "image_url", "image_url": {
                    "url": f"data:{ct};base64,{base64.b64encode(data).decode()}"}},
                {"type": "text", "text": "Describe this diagram or screenshot concisely for a support KB."},
            ]}])
            yield Document(page_content=msg.content, metadata=meta)
        elif ct == "application/pdf":
            for doc in PyPDFLoader(tmp_path).load():
                doc.metadata.update(meta); yield doc
        else:
            for doc in UnstructuredFileLoader(tmp_path).load():
                doc.metadata.update(meta); yield doc


def ingest_file(file_id: str, tenant_id: str) -> None:
    docs = list(PlatformFileLoader(file_id, tenant_id).lazy_load())
    if not docs:
        return
    _add_to_pg(docs, tenant_id)


# ── Track B: OKF bundle (platform-maintained structured knowledge) ─────────────

def load_okf_bundle(bundle_dir: str, tenant_id: str) -> list[Document]:
    """Parse OKF concepts. Frontmatter scalars → metadata; body → page_content."""
    docs = []
    for md_path in sorted(Path(bundle_dir).rglob("*.md")):
        if md_path.name in OKF_RESERVED:
            continue
        text = md_path.read_text(encoding="utf-8")
        if text.startswith("---"):
            _, fm_raw, body = text.split("---", 2)
            fm = yaml.safe_load(fm_raw) or {}
        else:
            fm, body = {}, text
        docs.append(Document(
            page_content=body.strip(),
            metadata={
                "tenant_id": tenant_id,
                "concept_id": str(md_path.relative_to(bundle_dir).with_suffix("")),
                **{k: str(v) for k, v in fm.items()
                   if isinstance(v, (str, int, float, bool))},
            },
        ))
    return docs


def _index_okf_to_pg(docs: list[Document], tenant_id: str) -> None:
    """Write OKF frontmatter into okf_concepts for exact SQL counts and lookups."""
    with psycopg.connect(os.environ["DATABASE_URL"]) as conn:
        conn.execute("""CREATE TABLE IF NOT EXISTS okf_concepts (
            tenant_id TEXT, concept_id TEXT, type TEXT, title TEXT,
            description TEXT, resource TEXT, tags TEXT, status TEXT, stale_after TEXT
        )""")
        conn.execute("DELETE FROM okf_concepts WHERE tenant_id = %s", [tenant_id])
        for doc in docs:
            m = doc.metadata
            conn.execute("INSERT INTO okf_concepts VALUES (%s,%s,%s,%s,%s,%s,%s,%s,%s)", (
                tenant_id, m.get("concept_id",""), m.get("type",""), m.get("title",""),
                m.get("description",""), m.get("resource",""), m.get("tags",""),
                m.get("status",""), m.get("stale_after",""),
            ))
        conn.commit()


def ingest_bundle(bundle_dir: str, tenant_id: str) -> None:
    docs = load_okf_bundle(bundle_dir, tenant_id)
    if not docs:
        return
    _index_okf_to_pg(docs, tenant_id)   # structured index for exact queries
    _add_to_pg(docs, tenant_id)         # pgvector + PostgreSQL FTS


# ── Shared: chunk and upsert into PostgreSQL pgvector + full-text search ───────

def _add_to_pg(docs: list[Document], tenant_id: str) -> None:
    chunks = RecursiveCharacterTextSplitter(
        chunk_size=800, chunk_overlap=100,
    ).split_documents(docs)

    doc_ids = []
    for chunk in chunks:
        m = chunk.metadata
        origin = m.get("concept_id") or m.get("file_id") or m.get("source", "")
        doc_id = hashlib.sha256(
            f"{tenant_id}:{origin}:{chunk.page_content}".encode()
        ).hexdigest()
        m.update({"tenant_id": tenant_id, "doc_id": doc_id})
        doc_ids.append(doc_id)

    PGVector(
        connection=os.environ["DATABASE_URL"],
        embeddings=embeddings,
        collection_name=f"kb_{tenant_id.replace('-','_')}",
    ).add_documents(chunks, ids=doc_ids)

    with psycopg.connect(os.environ["DATABASE_URL"]) as conn:
        conn.execute("""CREATE TABLE IF NOT EXISTS kb_fts (
            tenant_id TEXT NOT NULL,
            doc_id TEXT NOT NULL,
            concept_id TEXT,
            concept_type TEXT,
            title TEXT,
            status TEXT,
            content TEXT NOT NULL,
            search_vector TSVECTOR GENERATED ALWAYS AS (
                setweight(to_tsvector('english', coalesce(title, '')), 'A') ||
                setweight(to_tsvector('english', content), 'B')
            ) STORED,
            PRIMARY KEY (tenant_id, doc_id)
        )""")
        conn.execute(
            "CREATE INDEX IF NOT EXISTS kb_fts_search_idx "
            "ON kb_fts USING GIN (search_vector)"
        )
        for chunk in chunks:
            m = chunk.metadata
            conn.execute(
                """INSERT INTO kb_fts
                   (tenant_id, doc_id, concept_id, concept_type, title, status, content)
                   VALUES (%s,%s,%s,%s,%s,%s,%s)
                   ON CONFLICT (tenant_id, doc_id) DO UPDATE
                   SET concept_id=EXCLUDED.concept_id,
                       concept_type=EXCLUDED.concept_type,
                       title=EXCLUDED.title,
                       status=EXCLUDED.status,
                       content=EXCLUDED.content""",
                (tenant_id, m["doc_id"], m.get("concept_id", ""),
                 m.get("type", ""), m.get("title", ""), m.get("status", ""),
                 chunk.page_content),
            )
        conn.commit()
```

## <Label color="amber">4</Label> Platform MCP server

Your platform needs to expose an MCP server with at least these tools. The exact implementation is yours — DeepAgents calls them as black boxes.

Treat `email` as a lookup selector, not an authorization boundary. Every tool derives the tenant from the verified MCP request context before reading or mutating data:

```python
# platform_mcp_server.py — your platform code, not DeepAgents
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("StreamAPI Platform")

@mcp.tool()
def get_customer_state(email: str) -> dict:
    """Return account config, active API keys, tier, last login, feature flags."""
    tenant_id = auth_context.current_tenant_id()
    return your_db.query_customer(tenant_id=tenant_id, email=email)

@mcp.tool()
def fetch_logs(email: str, since: str, level: str = "ERROR") -> list[dict]:
    """Return recent log entries for a customer. since accepts ISO8601."""
    tenant_id = auth_context.current_tenant_id()
    return your_logging.query(tenant_id=tenant_id, customer=email, since=since, level=level)

@mcp.tool()
def apply_fix(action: str, target: str, **kwargs) -> dict:
    """Apply a remediation action. Supported: regenerate_key, reset_rate_limit, enable_feature."""
    tenant_id = auth_context.current_tenant_id()
    return your_admin.execute(tenant_id=tenant_id, action=action, target=target, **kwargs)

@mcp.tool()
def send_notification(email: str, subject: str, body: str) -> dict:
    """Send an email to the customer."""
    tenant_id = auth_context.current_tenant_id()
    return your_mailer.send(tenant_id=tenant_id, to=email, subject=subject, body=body)

if __name__ == "__main__":
    mcp.run(transport="sse", host="0.0.0.0", port=8080)
```

The MCP server or HTTP tool must derive tenant identity from the verified request context. Never let the model choose the tenant boundary by passing an arbitrary `tenant_id` or email to an unrestricted database query.

MCP tools are async, so the agent setup lives in an async function:

```python
# agent.py
import asyncio, hashlib, os, psycopg
from langchain_aws import BedrockEmbeddings
from langchain_postgres import PGVector
from langchain_core.tools import tool
from langchain_litellm import ChatLiteLLM
from langchain_mcp_adapters.client import MultiServerMCPClient
from deepagents import create_deep_agent
from deepagents.backends import FilesystemBackend
from deepagents.middleware.filesystem import FilesystemPermission
from langgraph.checkpoint.memory import MemorySaver

def make_model(**kw):
    """LiteLLM routes to any backend. LLM_MODEL must be set — no default.
    Credentials are per-backend: AWS IAM chain for Bedrock, ANTHROPIC_API_KEY,
    OPENAI_API_KEY, etc. Set LITELLM_API_BASE only when routing via a proxy."""
    return ChatLiteLLM(
        model=os.environ["LLM_MODEL"],
        api_base=os.environ.get("LITELLM_API_BASE"),
        temperature=0,
        **kw,
    )


# ── Retrieval tools — built per request with tenant_id baked in ───────────────
# tenant_id comes from the authenticated request context, never from model args.

_emb = BedrockEmbeddings(model_id="amazon.titan-embed-text-v2:0",
                          region_name=os.environ.get("AWS_REGION", "us-east-1"))

def make_kb_tools(tenant_id: str):
    """Return search_kb, lookup_openapi, catalog_count scoped to tenant_id."""
    pg_store = PGVector(
        connection=os.environ["DATABASE_URL"],
        embeddings=_emb,
        collection_name=f"kb_{tenant_id.replace('-','_')}",
    )


    @tool
    def search_kb(query: str, concept_type: str = "") -> list[dict]:
        """Hybrid pgvector + PostgreSQL FTS over uploaded docs and OKF concepts."""
        metadata_filter: dict = {"tenant_id": tenant_id}
        if concept_type:
            metadata_filter["type"] = concept_type
        vector_docs = pg_store.similarity_search(
            query, k=8, filter=metadata_filter,
        )

        sql = """WITH q AS (
                     SELECT websearch_to_tsquery('english', %s) AS query
                 )
                 SELECT doc_id, concept_id, concept_type, title, status, content
                 FROM kb_fts, q
                 WHERE tenant_id = %s AND search_vector @@ q.query"""
        params: list = [query, tenant_id]
        if concept_type:
            sql += " AND concept_type = %s"
            params.append(concept_type)
        sql += " ORDER BY ts_rank_cd(search_vector, q.query) DESC LIMIT 8"
        with psycopg.connect(os.environ["DATABASE_URL"]) as conn:
            fts_rows = conn.execute(sql, params).fetchall()

        # Reciprocal-rank fusion: reward chunks returned by both retrieval paths.
        merged: dict[str, dict] = {}
        for rank, doc in enumerate(vector_docs, start=1):
            key = doc.metadata.get("doc_id") or hashlib.sha256(
                doc.page_content.encode()
            ).hexdigest()
            merged[key] = {
                "content": doc.page_content,
                "concept_id": doc.metadata.get("concept_id", ""),
                "type": doc.metadata.get("type", ""),
                "title": doc.metadata.get("title", ""),
                "status": doc.metadata.get("status", ""),
                "_score": 1 / (60 + rank),
            }
        for rank, row in enumerate(fts_rows, start=1):
            item = merged.setdefault(row[0], {
                "content": row[5],
                "concept_id": row[1] or "",
                "type": row[2] or "",
                "title": row[3] or "",
                "status": row[4] or "",
                "_score": 0,
            })
            item["_score"] += 1 / (60 + rank)

        ranked = sorted(merged.values(), key=lambda item: item["_score"], reverse=True)
        return [{k: v for k, v in item.items() if k != "_score"} for item in ranked[:8]]

    @tool
    def lookup_openapi(path: str = "", method: str = "") -> list[dict]:
        """Exact SQL lookup of API endpoint contracts from the OKF structured index.
        Returns all matching rows — not limited by embedding similarity.
        Use for: 'list every endpoint under /orders', 'does POST /keys/rotate exist?'"""
        sql = """SELECT concept_id, title, resource, description, status
                   FROM okf_concepts WHERE tenant_id = %s AND type = 'API Endpoint'"""
        params: list = [tenant_id]
        if path:
            sql += " AND resource LIKE %s"; params.append(f"%{path}%")
        if method:
            sql += " AND title LIKE %s"; params.append(f"%{method.upper()}%")
        with psycopg.connect(os.environ["DATABASE_URL"]) as conn:
            rows = conn.execute(sql, params).fetchall()
        return [
            {"concept_id": r[0], "title": r[1], "resource": r[2],
             "description": r[3], "status": r[4]}
            for r in rows
        ]

    @tool
    def catalog_count(concept_type: str) -> dict:
        """Exact SQL count of OKF concepts of a given type for this tenant.
        Use for: 'how many API endpoints do we have?', 'how many current policies?'"""
        with psycopg.connect(os.environ["DATABASE_URL"]) as conn:
            n = conn.execute(
                "SELECT COUNT(*) FROM okf_concepts WHERE tenant_id = %s AND type = %s",
                [tenant_id, concept_type],
            ).fetchone()[0]
        return {"concept_type": concept_type, "count": n}

    return search_kb, lookup_openapi, catalog_count


# ── Build agent ────────────────────────────────────────────────────────────────

async def build_agent(tenant_id: str):
    search_kb, lookup_openapi, catalog_count = make_kb_tools(tenant_id)
    mcp = MultiServerMCPClient({
        "platform": {
            "url": "http://localhost:8080/sse",
            "transport": "sse",
        }
    })
    platform_tools = await mcp.get_tools()

    return create_deep_agent(
        model=make_model(),
        tools=[search_kb, lookup_openapi, catalog_count, *platform_tools],

        # Runbooks + escalation rules always loaded
        # Static policy only — never put customer state in AGENTS.md
        memory=["./AGENTS.md"],

        # Domain knowledge loaded progressively per task
        # ./skills/401-errors/SKILL.md  ← detailed 401 investigation checklist
        # ./skills/customer-tiers/SKILL.md ← tier-specific SLA rules
        skills=["./skills/"],

        # Filesystem for scratch notes during investigation
        backend=FilesystemBackend(root_dir="./workspace"),

        permissions=[
            # Deny writes to sensitive paths — paths MUST start with /
            FilesystemPermission(operations=["read", "write"], paths=["/**/.env"],       mode="deny"),
            FilesystemPermission(operations=["read", "write"], paths=["/billing/**"],    mode="deny"),
            # HITL on customer data writes
            FilesystemPermission(operations=["write"],          paths=["/customers/**"], mode="interrupt"),
        ],

        # Required for interrupt/resume state; use a durable saver in production
        checkpointer=MemorySaver(),

        # Optional: durable cross-session facts, namespaced by tenant/user
        # store=tenant_scoped_store,

        # Pause before apply_fix or send_notification — human approves
        interrupt_on={
            "apply_fix":         True,
            "send_notification": True,
        },

        system_prompt="""You are a customer support agent for StreamAPI.

**Retrieval strategy — follow this order for every question:**
1. Analyze the query: clean it, classify intent, and identify the OKF concept type if applicable.
2. For general questions → call search_kb (optionally pass concept_type='Playbook', 'Policy', etc.).
3. For API contract questions → call lookup_openapi with path/method filters.
4. For counts → call catalog_count with the relevant concept_type.
5. After retrieval, evaluate: does the evidence support the answer? If not, try the next strategy (max 2 retries), then escalate.
6. For live diagnostics after KB retrieval fails → call search_logs or get_trace from platform tools.

**Investigation steps:**
1. Classify and retrieve — pick the right strategy above.
2. Call get_customer_state — inspect account, keys, tier, feature flags.
3. Call fetch_logs — find the specific error with timestamp and tenant scope.
4. Diagnose the root cause precisely. Cite the KB article, OpenAPI field, or log line.
5. Propose a fix with rationale — you will pause for human approval before applying.

Escalate if: data loss or security exposure detected, cannot diagnose within 3 tool calls, or evidence is absent.
""",
    )

```

## <Label color="teal">6</Label> A complete troubleshooting session

Invoke the agent with the customer's report:

```python
# support_request.py
```

## <Label color="rose">7</Label> Evaluator and tool fallback

Retrieval can fail silently — the store returns five chunks, but none of them support the answer. An evaluator step catches this before the agent fabricates a response.

```python
EVALUATOR_PROMPT = """
You are evaluating whether the retrieved context supports a grounded answer.

Question: {question}
Retrieved context:
{context}

Respond with:
- SUPPORTED: context contains evidence for a direct answer. Cite the source.
- INSUFFICIENT: context does not cover the question. Suggest the next strategy.
- ESCALATE: question requires human judgment or live data that no tool can resolve.
"""
```

Wire the evaluator as a post-retrieval step in your agent's system prompt or as a dedicated LangGraph node before the answer is emitted. Bound fallback retries at 2 — a third failure escalates rather than loops.

## <Label color="amber">8</Label> AGENTS.md — what to put in memory

The `memory=["./AGENTS.md"]` file is loaded on every session. It contains durable policy only — escalation rules, tone, and known platform behavior. It is shared by the agent, not by an individual customer. Store account state, ticket history, preferences, and audit records in your tenant-scoped application database instead.

```markdown
# StreamAPI Support Agent

## Escalation rules
- Data loss or security exposure → page on-call immediately, do not attempt fix
- Customer on Enterprise tier → always loop in account manager before fixing
- SLA breach (>4h open on Pro, >1h on Enterprise) → auto-escalate

## Known platform issues (update weekly)
- Key rotation emails sometimes land in spam → always mention this in notifications
- Rate limit reset takes up to 5 min to propagate — wait before retesting

## Tone
- Be direct. No filler. Cite the specific log line or KB article.
- Always tell the customer what you found, not just what you did.
```

The MCP implementation above is where this tenant check belongs. Whether the agent reaches it through MCP or a directly wrapped HTTP tool, the server must derive the tenant from verified authentication before querying or mutating customer data.

If the agent needs durable facts across sessions, use a persistent store with a namespace such as `("tenant", tenant_id, "user", user_id)`. The current investigation still belongs to the checkpointer's `thread_id`; the database and store hold long-lived domain state.

## <Label color="blue">10</Label> MCP or direct HTTP?

MCP is a capability boundary, not a requirement. DeepAgents accepts ordinary LangChain tools too. For a small, stable internal API, a typed HTTP tool can be simpler than running an MCP server:

```python
# http_tools.py — fixed endpoint, typed inputs, no arbitrary URL access
import os
import httpx
from langchain_core.tools import tool

@tool
async def fetch_logs_http(email: str, since: str, level: str = "ERROR") -> list[dict]:
    """Read recent logs for a customer inside the authenticated tenant."""
    tenant_id = auth_context.current_tenant_id()
    async with httpx.AsyncClient(
        base_url="https://api.streamapi.io",
        timeout=10.0,
    ) as client:
        response = await client.get(
            "/internal/logs",
            params={"customer": email, "since": since, "level": level},
            headers={
                "Authorization": f"Bearer {os.environ['STREAMAPI_INTERNAL_TOKEN']}",
                "X-Tenant-ID": tenant_id,
            },
        )
        response.raise_for_status()
        return response.json()
```

Pass `fetch_logs_http` directly in `tools=[...]` and remove `MultiServerMCPClient`. Keep the same tenant checks, timeouts, redaction, and `interrupt_on` rules. Never expose a generic `url` or raw `requests.get` tool to the model.

Use direct HTTP for a few endpoints owned by the same team. Use MCP when capabilities are independently deployed, shared by multiple agents, or need standardized discovery and schemas.

## <Label color="violet">11</Label> LiteLLM — one interface, any backend

[LiteLLM](https://github.com/BerriAI/litellm) gives DeepAgents a single `ChatLiteLLM` interface over every major provider. The only variable is the model string; no provider-specific client classes. For this stack Bedrock is the default — reasoning and multimodal calls both route through it:

```python
# Set in environment or secret manager — never in code.
# LiteLLM model string format: "provider/model-id"
# LLM_MODEL=bedrock/anthropic.claude-sonnet-...  ← Bedrock (Sonnet 5)
# LLM_MODEL=anthropic/claude-sonnet-...          ← Anthropic direct
# LLM_MODEL=openai/gpt-4.1                       ← OpenAI
```

`make_model()` in `agent.py` reads `LLM_MODEL` at startup and returns a `ChatLiteLLM` instance — no code change needed to switch backends. The same model handles both text reasoning and multimodal image-to-text in the ingestion pipeline.

## <Label color="green">12</Label> Deploy the agent as a service

Build a tenant-scoped agent per request — one process-wide agent would answer every customer using the same KB. Cache agents per `tenant_id` to avoid rebuilding tenant-scoped retrieval tools and MCP connections on every call:

```python
# service.py
import os
from typing import Any
from uuid import uuid4
from fastapi import FastAPI, Request
from pydantic import BaseModel

app = FastAPI()

# Cache keyed by tenant_id — avoids rebuilding retrieval tools and MCP connections.
# Invalidate an entry when that tenant's KB is re-indexed.
_agent_cache: dict[str, Any] = {}

class SupportRequest(BaseModel):
    customer_email: str
    report: str

@app.post("/v1/troubleshoot")
async def troubleshoot(request: Request, body: SupportRequest):
    # tenant_id injected by auth middleware — never read from request body
    tenant_id: str = request.state.tenant_id

    if tenant_id not in _agent_cache:
        _agent_cache[tenant_id] = await build_agent(tenant_id=tenant_id)
    agent = _agent_cache[tenant_id]

    thread_id = str(uuid4())
    config = {"configurable": {"thread_id": thread_id}}
    result = await agent.ainvoke(
        {
            "messages": [{
                "role": "user",
                "content": (
                    f"Customer: {body.customer_email}\n"
                    f"Report: {body.report}"
                ),
            }]
        },
        config=config,
    )
    last_message = result["messages"][-1]
    return {
        "thread_id": thread_id,
        "status": "interrupted_or_complete",
        "reply": getattr(last_message, "content", str(last_message)),
    }
```

The production request path is: authenticated API request → tenant context → agent service → KB + MCP/HTTP tools → checkpointer interrupt → approval endpoint or queue → resume the same `thread_id`. Put the agent behind your existing API gateway; do not expose the model or internal tools directly to the browser.

```dockerfile

WORKDIR /app
COPY pyproject.toml uv.lock ./
RUN pip install uv && uv sync --frozen --no-dev
COPY . .
CMD ["uv", "run", "uvicorn", "service:app", "--host", "0.0.0.0", "--port", "8080"]
```


Before production, replace `MemorySaver()` with a durable checkpointer, run PostgreSQL/pgvector as a managed service with connection pooling and schema migrations, store tenant facts in the application database, and add authentication, rate limits, audit logs, tracing, secret-manager injection, and an approval endpoint that resumes the stored thread.
