A customer emails at 11pm: *"Getting 401s since 3pm, blocking our release."* Your on-call engineer opens four browser tabs — docs, logs dashboard, admin panel, runbook — and starts the same manual investigation they've done a hundred times.

This post wires [DeepAgents](https://github.com/langchain-ai/deepagents) to do that investigation automatically: ingest your KB into a searchable store, connect your platform via MCP, and run a troubleshooting agent that diagnoses the issue and proposes a fix — pausing for human approval before touching anything.

**Scenario throughout this post:** StreamAPI, a fictional SaaS platform. Customer `tai@streamapi.io` is getting 401 errors. We'll build the agent that figures out why.

This is the implementation-level companion to [Building Support Agents for Your Platform](/en/blog/building-support-agents-for-your-platform/), which covers the broader multi-agent topology, observability architecture, tenancy, evaluation, and production trade-offs. This post deliberately narrows to one DeepAgents-powered technical-support lane: KB retrieval + platform MCP tools + human approval before writes. It complements that architecture post; it does not replace it.

## <Label color="green">2</Label> KB ingestion pipeline

<Concept term="Why a separate ingestion step?" category="design">
  The agent queries the KB at runtime, but the KB itself is built offline. Keeping ingestion separate means the agent always queries a stable, pre-indexed store — not a live doc system that could be slow or unavailable mid-investigation.
</Concept>

Run this whenever your KB content changes — CI push, doc webhook, or a nightly cron:

```python
# ingest.py — run offline, not inside the agent
from langchain_community.document_loaders import DirectoryLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings
from langchain_community.vectorstores import Chroma

# Load from wherever your KB lives
# Swap for ConfluenceLoader, S3FileLoader, GitbookLoader, etc.
docs = DirectoryLoader("./kb-source/", glob="**/*.md").load()

# Chunk — 800 tokens is a good starting size for support docs
chunks = RecursiveCharacterTextSplitter(
    chunk_size=800,
    chunk_overlap=100,
).split_documents(docs)

# Build and persist the vector store
Chroma.from_documents(
    chunks,
    OpenAIEmbeddings(model="text-embedding-3-small"),
    persist_directory="./kb",
)
print(f"Ingested {len(chunks)} chunks from {len(docs)} documents.")
```

## <Label color="amber">3</Label> Platform MCP server

Your platform needs to expose an MCP server with at least these tools. The exact implementation is yours — DeepAgents calls them as black boxes.

Treat `email` as a lookup selector, not an authorization boundary. Every tool derives the tenant from the verified MCP request context before reading or mutating data:

```python
# platform_mcp_server.py — your platform code, not DeepAgents
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("StreamAPI Platform")

@mcp.tool()
def get_customer_state(email: str) -> dict:
    """Return account config, active API keys, tier, last login, feature flags."""
    tenant_id = auth_context.current_tenant_id()
    return your_db.query_customer(tenant_id=tenant_id, email=email)

@mcp.tool()
def fetch_logs(email: str, since: str, level: str = "ERROR") -> list[dict]:
    """Return recent log entries for a customer. since accepts ISO8601."""
    tenant_id = auth_context.current_tenant_id()
    return your_logging.query(tenant_id=tenant_id, customer=email, since=since, level=level)

@mcp.tool()
def apply_fix(action: str, target: str, **kwargs) -> dict:
    """Apply a remediation action. Supported: regenerate_key, reset_rate_limit, enable_feature."""
    tenant_id = auth_context.current_tenant_id()
    return your_admin.execute(tenant_id=tenant_id, action=action, target=target, **kwargs)

@mcp.tool()
def send_notification(email: str, subject: str, body: str) -> dict:
    """Send an email to the customer."""
    tenant_id = auth_context.current_tenant_id()
    return your_mailer.send(tenant_id=tenant_id, to=email, subject=subject, body=body)

if __name__ == "__main__":
    mcp.run(transport="sse", host="0.0.0.0", port=8080)
```

<Callout color="amber">
  DeepAgents will call `apply_fix` and `send_notification` automatically — but we'll add a human approval gate on those in the next step so nothing goes out unsupervised.
</Callout>

## <Label color="rose">4</Label> Wiring DeepAgents

Now connect all three pieces.

Before wiring the agent, separate **policy** from **state**. `memory=["./AGENTS.md"]` is a static prompt input — it is not a tenant database and should never contain customer-specific facts:

The MCP server or HTTP tool must derive tenant identity from the verified request context. Never let the model choose the tenant boundary by passing an arbitrary `tenant_id` or email to an unrestricted database query.

MCP tools are async, so the agent setup lives in an async function:

```python
# agent.py
import asyncio
from langchain_anthropic import ChatAnthropic
from langchain_community.vectorstores import Chroma
from langchain_openai import OpenAIEmbeddings
from langchain.tools.retriever import create_retriever_tool
from langchain_mcp_adapters.client import MultiServerMCPClient
from deepagents import create_deep_agent
from deepagents.backends import FilesystemBackend
from deepagents.middleware.filesystem import FilesystemPermission
from langgraph.checkpoint.memory import MemorySaver

# ── KB retrieval tool (sync — built once at startup) ──────────────────────────

kb_store = Chroma(
    persist_directory="./kb",
    embedding_function=OpenAIEmbeddings(model="text-embedding-3-small"),
)
kb_tool = create_retriever_tool(
    kb_store.as_retriever(search_kwargs={"k": 5}),
    name="search_kb",
    description=(
        "Search the StreamAPI knowledge base: runbooks, known issues, API changelog, "
        "tier definitions, escalation paths. Always search this before checking logs."
    ),
)

# ── Build agent (async because MCP tools require await) ───────────────────────

async def build_agent():
    mcp = MultiServerMCPClient({
        "platform": {
            "url": "http://localhost:8080/sse",
            "transport": "sse",
        }
    })
    platform_tools = await mcp.get_tools()   # get_customer_state, fetch_logs, apply_fix, send_notification

    return create_deep_agent(
        model=ChatAnthropic(model="claude-sonnet-4-5-20250929"),
        tools=[kb_tool, *platform_tools],

        # Runbooks + escalation rules always loaded
        # Static policy only — never put customer state in AGENTS.md
        memory=["./AGENTS.md"],

        # Domain knowledge loaded progressively per task
        # ./skills/401-errors/SKILL.md  ← detailed 401 investigation checklist
        # ./skills/customer-tiers/SKILL.md ← tier-specific SLA rules
        skills=["./skills/"],

        # Filesystem for scratch notes during investigation
        backend=FilesystemBackend(root_dir="./workspace"),

        permissions=[
            # Deny writes to sensitive paths — paths MUST start with /
            FilesystemPermission(operations=["read", "write"], paths=["/**/.env"],       mode="deny"),
            FilesystemPermission(operations=["read", "write"], paths=["/billing/**"],    mode="deny"),
            # HITL on customer data writes
            FilesystemPermission(operations=["write"],          paths=["/customers/**"], mode="interrupt"),
        ],

        # Required for interrupt/resume state; use a durable saver in production
        checkpointer=MemorySaver(),

        # Optional: durable cross-session facts, namespaced by tenant/user
        # store=tenant_scoped_store,

        # Pause before apply_fix or send_notification — human approves
        interrupt_on={
            "apply_fix":         True,
            "send_notification": True,
        },

        system_prompt="""You are a customer support agent for StreamAPI.

When investigating an issue:
1. search_kb first — find the relevant runbook or known issue
2. get_customer_state — inspect their account, keys, tier, feature flags
3. fetch_logs — find the specific error (use the customer's email and the reported timeframe)
4. Diagnose the root cause precisely
5. Propose a fix with rationale — you will pause for human approval before applying

Always cite which KB article or log entry led to your conclusion.
If the issue matches a known bug, say so and link the workaround.
Escalate to on-call if you find data loss, security exposure, or cannot diagnose within 3 tool calls.
""",
    )

```

## <Label color="teal">5</Label> A complete troubleshooting session

Invoke the agent with the customer's report:

```python
# support_request.py
async def troubleshoot():
    agent = await build_agent()
    config = {"configurable": {"thread_id": "streamapi-tai-401"}}
    paused = await agent.ainvoke(
        {
            "messages": [{
                "role": "user",
                "content": """
                Customer: tai@streamapi.io
                Reported: 2026-09-11 11:04pm
                Issue: Getting 401 Unauthorized on all API calls since ~3pm today.
                Blocking our release — we're on Pro tier, SLA applies.
                """
            }]
        },
        config=config,
    )
    return agent, config, paused

agent, config, result = asyncio.run(troubleshoot())
```

The first `ainvoke` returns an interrupt before the write tools run. Keep the `agent` and `config` returned by `troubleshoot()` in the same async worker, then resume after the human approves both pending write actions:

```python
from langgraph.types import Command

async def approve_and_resume(agent, config):
    return await agent.ainvoke(
        Command(resume={
            "decisions": [{"type": "approve"}, {"type": "approve"}]
        }),
        config=config,
    )
```

## <Label color="amber">6</Label> AGENTS.md — what to put in memory

The `memory=["./AGENTS.md"]` file is loaded on every session. It contains durable policy only — escalation rules, tone, and known platform behavior. It is shared by the agent, not by an individual customer. Store account state, ticket history, preferences, and audit records in your tenant-scoped application database instead.

```markdown
# StreamAPI Support Agent

## Escalation rules
- Data loss or security exposure → page on-call immediately, do not attempt fix
- Customer on Enterprise tier → always loop in account manager before fixing
- SLA breach (>4h open on Pro, >1h on Enterprise) → auto-escalate

## Known platform issues (update weekly)
- Key rotation emails sometimes land in spam → always mention this in notifications
- Rate limit reset takes up to 5 min to propagate — wait before retesting

## Tone
- Be direct. No filler. Cite the specific log line or KB article.
- Always tell the customer what you found, not just what you did.
```

The MCP implementation above is where this tenant check belongs. Whether the agent reaches it through MCP or a directly wrapped HTTP tool, the server must derive the tenant from verified authentication before querying or mutating customer data.

If the agent needs durable facts across sessions, use a persistent store with a namespace such as `("tenant", tenant_id, "user", user_id)`. The current investigation still belongs to the checkpointer's `thread_id`; the database and store hold long-lived domain state.
