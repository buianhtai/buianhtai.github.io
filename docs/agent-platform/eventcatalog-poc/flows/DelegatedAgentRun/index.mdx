# Bounded Agent-to-Agent Delegation

**Status: proposed design, not deployed workflow code.** Native EventCatalog Flow nodes below link directly to referenced services, commands and events.

<NodeGraph />

## When to use delegation

Delegation is not the same as routing or invoking a tool. Routing chooses the **initial agent**. Tool invocation operates through the Tool Gateway. Delegation starts a **new child AgentRun** for one approved specialist with its own pinned agent version, resource grants, budget and audit trail.

## Fictional example

A research coordinator receives: "Compare two public integration guides and summarize the breaking differences." The parent publishes a narrow evidence-gathering task to a read-only documentation specialist, waits on durable child completion, validates citation references and returns the summary. The child has no ability to read the parent's private notes or invoke its other tools.

## Lineage and safeguards

~~~mermaid
sequenceDiagram
    participant P as Parent Worker
    participant D as Delegation Gateway
    participant R as Run Service
    participant C as Child Worker
    P->>D: DelegateAgentRun(alias, taskRef, budget)
    D->>D: Check binding, depth and intersection of grants
    D->>R: Admit child with parentRunId + reservation
    R->>C: Start pinned specialist version
    C-->>R: Persist bounded result + usage
    R-->>D: ChildRunCompleted
    D-->>P: Typed resultRef
    P->>P: Join evidence and compose final answer
~~~

The parent sees only the allowed alias. Budget reservations prevent fan-out from exceeding the parent's hard cost limit; maximum depth and child count are enforced by platform code. Cancellation propagates best effort. Repeated delegationId requests reuse the same child; late results are recorded but cannot mutate a finalized parent without a new authorized run.

## Failure modes

If a specialist is undeployed, deny before spending. If the child times out, return a typed timeout and release unused reserved budget. If the parent is cancelled, cancel children and remote tasks where supported. External A2A agents require a separate trusted adapter with origin verification and data-egress policy; they are not enabled by a simple MCP tool binding.
