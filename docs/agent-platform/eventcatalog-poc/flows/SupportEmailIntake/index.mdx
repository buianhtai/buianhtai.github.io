# Scheduled Support Email Intake

**Status: proposed design, not deployed workflow code.** Native EventCatalog Flow nodes below link directly to referenced services, commands and events.

<NodeGraph />

<CustomProperties title="Architecture governance" />

## Business purpose

Process an inbound support mailbox without paying for a frontier model on every email. **External scheduling or email connectors trigger the workflow; the agent does not poll mail directly.** The initial version is deliberately human-reviewed for outbound mail.

## Example walkthrough

A fictional customer writes: "Where is the public authentication guide?" A verified mailbox adapter records the source message ID. Deterministic rules recognize a documentation question, then a low-cost read-only knowledge search supplies source references. A short draft is produced and placed in a review queue; an authorized human approves the exact recipient and content before a registered outbound connector sends it.

## Cost and escalation policy

| Condition | Route | Relative cost |
| --- | --- | --- |
| Spam/duplicate | Rules only; ignore and audit | Minimal |
| Simple known FAQ | Template draft; human review | No LLM required |
| Ambiguous issue | Bounded classifier, then knowledge retrieval | Small model |
| Sensitive, low confidence or missing sources | Human escalation; no fabricated answer | Avoid unnecessary model loop |
| Complex technical request | Optional specialist after explicit policy | Capped, measured escalation |

## Reliability and safety

Deduplicate incoming source IDs and outgoing send intents separately. Email body and attachments are untrusted instructions; never let them override agent grants or execute arbitrary tools. Consent/retention and sensitive-data handling belong to tenant policy. A failed send may have succeeded remotely; correlate external message ID before retrying. User-visible progress derives from the durable Run Service, not the mail provider's callback.

## Acceptance checks

Duplicate polls create one logical intake record. Invalid source verification cannot run a model. No customer reply is sent without an unexpired approval bound to exact content/recipient. Missing evidence escalates instead of hallucinating. Record per-email token cost, classifier accuracy, draft acceptance, and manual intervention rate.
