## Interpretation

Public HTTP handlers are **not the place to execute LLM loops**. They establish authenticated scope, resolve one authorized agent, admit work idempotently and expose a durable read projection. The registry resolves a pinned version; Run Service owns acceptance. Separate logical responsibilities may share a process in the MVP.

## Proposed interface boundaries

| Port | Request | Authority | Idempotency/trace |
| --- | --- | --- | --- |
| Run admission | POST /v1/runs | Principal, tenant and deployment ACL | Idempotency-Key + body hash; 202 only after commit |
| Current state | GET /v1/runs/:runId | Per-run authorization | Correlated trace and safe result refs |
| Events | GET /v1/runs/:runId/events | Subscription is reauthorized | Ordered cursor; stale cursor -> snapshot |
| Publish | POST /v1/agents/:agentId/publish | Publisher role and grants | Immutable version digest and audit event |

## Routing rule

Explicit agent selection bypasses ranking. Automatic routing filters eligible published deployments first; uncertainty asks for selection instead of invoking multiple agents without permission. Documentation contracts are proposed and require real implementation evidence before marking Implemented.
