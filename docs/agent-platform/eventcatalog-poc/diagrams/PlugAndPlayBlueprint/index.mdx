# Plug-and-Play Agent Platform — Product Blueprint

**Status: proposed, vendor-neutral reference architecture.** No named connector or model is implied to be deployed, and no plugin bypasses policy.

## Core reading

**Configuration is not execution.** An author assembles eligible parts of an agent; the Registry's logical compiler validates and pins a version; the Run Service admits execution; separate workers run through model/tool/delegation gateways. A trusted operator's reviewed AdapterPackage is **not** automatically visible as a runnable tool, and published capabilities do not automatically give an agent permission.

### Extension and configuration boundaries

| Object | Who manages it | Stability and permission |
| --- | --- | --- |
| AdapterPackage | Operator | Reviewed code/distribution, typed port and pinned version |
| AdapterInstance | Operator/workspace admin | Workspace endpoint, credential reference, health and egress |
| Published Capability | Platform admin/catalog owner | Stable reviewed operation/schema and risk class |
| AgentBinding | Agent author with grants | Narrower versioned scopes; never expands operator permission |
| AgentVersion | Authorized publisher | Immutable manifest digest of model, skills, knowledge, tools, triggers and permitted subagents |
| AgentRun | Platform backend | Pinned published revision, hard runtime budget, durable events |

The **Agent Compiler** is a logical control-plane responsibility, not an independently required microservice. Skills are instructions/data, not scripts that install new permissions. Knowledge sources are scoped and versioned independently from the tools that retrieve them.
