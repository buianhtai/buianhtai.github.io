# Tool Gateway

**Status: proposed logical component; not evidence of a deployed service.**

<CustomProperties title="Architecture governance" />

## Tool is not connector

A ToolDefinition specifies a versioned reviewed capability and input/output schemas. A connector instance identifies the approved MCP/HTTP/job integration and secret reference. An AgentVersion ToolBinding narrows allowed operations, arguments, scope, call count and approval. A ToolInvocation records a single attempt and outcome.

## Plug-and-play invocation

~~~mermaid
flowchart LR
  A["Bound tool request"] --> G["Tool Gateway"]
  G --> P{"Schema, tenant ACL, budget, risk"}
  P -->|No| X["Deny + audit"]
  P -->|Yes| T{"Reviewed adapter"}
  T --> M["MCP"]
  T --> H["Typed HTTP"]
  T --> J["Approved external job"]
~~~

| Stage | Required check |
| --- | --- |
| Resolve | Pinned tool version, registered adapter and operation |
| Authorize | Principal ∩ agent binding ∩ tenant resource ACL |
| Validate | Closed JSON schema, request size, egress allowlist |
| Bound | Per-run calls, timeout, rate/concurrency and monetary limit |
| Approve | For writes, human review of exact immutable intent |
| Execute | Scoped secret reference, remote ID and idempotency key |
| Finish | Normalized outcome and audit, including OUTCOME_UNKNOWN |

For remote scripts use a **signed/pinned named operation**, not arbitrary shell text or URLs. If a remote write times out after acceptance, correlate its job ID before attempting any retry.

**Example:** [ApprovalGatedExternalJob](/architecture/docs/flows/ApprovalGatedExternalJob/0.1.0/).
