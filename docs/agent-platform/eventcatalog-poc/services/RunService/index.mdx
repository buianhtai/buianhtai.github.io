# Run Service

**Status: proposed logical component; not evidence of a deployed service.**

<NodeGraph />

<CustomProperties title="Architecture governance" />

## Durability first

One transaction commits runId, tenant/principal, idempotency claim, pinned immutable AgentVersion digest, effective policy/budget, input reference and outbox dispatch intent. No HTTP 202 is returned before commit. The dispatcher can deliver a run more than once, but the Run Service admits one logical run.

## Public status vocabulary

| Status | Meaning |
| --- | --- |
| QUEUED | Durable acceptance; awaiting capacity or retry |
| RUNNING | Fenced worker attempt owns execution |
| WAITING_APPROVAL | Exact side-effect intent needs a reviewer |
| WAITING_EXTERNAL_JOB | Remote job is outstanding; status must reconcile |
| SUCCEEDED / FAILED / CANCELLED | Terminal projection and result reference |

A workflow engine may own internal checkpoints and timers; it must not compete with the Run Service for public run status. Commit terminal transitions atomically and reject a stale fencing token.

## Safety and telemetry

An unknown external write result is distinct from failure; do not blindly retry. Events include stable runId, monotonic per-run sequence, traceId and safe outcome, with detailed artifacts behind authorization. Measure admitted runs, queue age, retry exhaustion, successful recovery and spend per run.

**Model:** [AgentRun](/architecture/docs/entities/AgentRun/0.1.0/) · **Flow:** [AgentRunRecovery](/architecture/docs/flows/AgentRunRecovery/0.1.0/).

## Lifecycle contract authority

The local **AsyncAPI 3** specification is a proposed broker-facing event model. The `RunAccepted`, `RunStarted`, `RunCompleted` and `RunFailed` EventCatalog message resources provide the **versioned canonical field names** to validate against. The event store is authoritative for ordering and replay; AsyncAPI describes what consumers may subscribe to, not transport exactly-once behavior.

On implementation, generate or synchronize from the source event schema rather than manually maintaining divergent copies, and record any compatibility break as a new message version.
