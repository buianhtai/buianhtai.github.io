# Platform API

**Status: proposed logical component; not evidence of a deployed service.**

<NodeGraph />

<CustomProperties title="Architecture governance" />

## Boundary

Platform API authenticates people and integrations, checks workspace/tenant access, validates request shape and idempotency, and delegates run admission to the Run Service. The browser receives **202 only after a durable run/outbox transaction**; it never waits synchronously for an LLM to finish.

## Proposed API

~~~http
POST /v1/runs
Idempotency-Key: session-01-message-02
Content-Type: application/json

{"target":{"type":"deployment","id":"documentation-agent:prod"},"input":{"message":"How does authentication work?"}}
~~~

| Interface | Responsibility |
| --- | --- |
| POST /v1/runs | Authorized durable run admission |
| GET /v1/runs/:runId | Tenant-scoped status, resultRef and metering |
| GET /v1/runs/:runId/events | Replayable authenticated SSE |
| POST /v1/agents/:agentId/publish | Registry-backed validation and immutable publication |

## Failure and operations

Duplicate idempotency keys return the same logical run for the same payload, conflicting inputs get HTTP 409. Use typed 401/403/404/429 without leaking cross-tenant resource existence. Track p95 admission latency, rejection rate and API concurrency. Workers, tool execution, model calls and SSE state remain behind their owning components.

**Journey:** [ExplicitAgentRun](/architecture/docs/flows/ExplicitAgentRun/0.1.0/).

## Public API versus internal commands

The local **OpenAPI 3.1** specification on this service page is a proposed **external** REST boundary. The `StartAgentRun` command is a *normalized internal intent* with its own separate JSON Schema. The Platform API authenticates and verifies `target`, derives the effective principal and published manifest, then passes a policy-safe form to the Run Service. Their payloads intentionally differ; version both independently.

For implementation use the OpenAPI contract as a discussion baseline only; align path, errors, ID types, schema validation and auth with the actual service implementation before marking anything delivered. There is no live server at the illustrative `example.invalid` host.
