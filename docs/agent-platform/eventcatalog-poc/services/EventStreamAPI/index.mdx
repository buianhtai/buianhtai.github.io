# Event Streaming API

**Status: proposed logical component; not evidence of a deployed service.**

<NodeGraph />

<CustomProperties title="Architecture governance" />

## Client result path

The worker persists normalized events; the API reads the event store and authenticates each subscription. A browser never connects directly to a worker, and disconnecting the UI **never restarts** execution.

~~~text
GET /v1/runs/run-example/events
Last-Event-ID: 41

id: 42
event: run.completed
data: {"runId":"run-example","status":"SUCCEEDED","resultRef":"artifact-example"}
~~~

## Replay behavior

Use a monotonic event cursor per run and a configured retention period. On reconnect, replay committed entries after Last-Event-ID; on expired cursor return an explicit cursor-expired error plus a status snapshot path. Large/sensitive content remains behind scoped artifact references instead of broadcast events.

| Incident | Contract |
| --- | --- |
| Proxy idle timeout | Client reconnects with cursor |
| Duplicate notification | Client deduplicates by event sequence |
| Worker failure | Existing events and terminal projection remain durable |
| Access revoked | Reject subscription and artifact access |
| Old cursor | Return typed expiration and latest status |

Track active connections, time-to-first-update, reconnect rate and event replay lag.
