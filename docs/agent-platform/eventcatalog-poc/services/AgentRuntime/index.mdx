# Agent Runtime

**Status: proposed logical component; not evidence of a deployed service.**

<NodeGraph />

<CustomProperties title="Architecture governance" />

## Loop contract

An approved RuntimeAdapter receives pinned manifest digest, scoped context, session/checkpoint reference, available tool **schemas** and budget. It asks an approved model for a next step, forwards any proposed tool call to the Tool Gateway, handles validated evidence and produces a typed final result. The runtime **does not route the initial user request** or grant its own permissions.

~~~mermaid
flowchart TD
    A["Pinned config + scoped context"] --> B["Model Gateway"]
    B --> C{"Tool requested?"}
    C -->|No| D["Validate structured answer"]
    C -->|Yes| E["Tool Gateway authorizes call"]
    E --> F["Sanitize result and checkpoint"]
    F --> G{"Hard budget / step limit met?"}
    G -->|No| B
    G -->|Yes| H["Typed partial / limit outcome"]
~~~

## Runtime policies

Enforce maximum turns, tokens, tool calls, total spend, timeout, cancellation and maximum delegated children in trusted code, **not solely prompts**. Model errors, missing sources and invalid tool arguments return typed failures. A simple loop is enough for bounded read-only tasks; a graph runtime may be configured for complex checkpointed execution. Both produce the same platform events.
